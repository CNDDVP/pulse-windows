# StepFun 与机器人修复交付

基于用户两批未提交施工继续修改，保留原有改动。版本统一为 0.6.0。

## 已实现

- StepFun 的所有现有保存入口共用后端合并：空白/未提供字段保留已有 Secret，更新 Key 不删除 Token，更新 Token 不删除 Key。仍通过原有删除按钮删除整组凭据。配置写入失败时回滚凭据；凭据读取失败不再视为空值覆盖。
- API 与网页请求并发；成功结果分别筛选再合并，现金仅使用官方 balance 字段。任一来源失败，保留另一来源有效数据，并显示具体来源及错误；未配置来源有明确提示，不把网络失败统一称为 Token 过期。
- 详情卡及设置用量区同时显示“API 可用余额 ¥…”、“套餐剩余 … 亿 Credit”及套餐百分比。所有数值来自读数，15 元不是预设实际余额。
- 清除成功读数的虚假 no_data 消息；兼容字符串重置时间；有效零 Credit 保留；未知账期不再写死 30 天；未取得正式套餐名时显示中性名称。
- 纯余额主环不再强制关闭独立选择的第二内环和时间环。
- 机器人庆祝比较实际选中的窗口值，并要求同一窗口周期推进、双方 live 读数及足够跌幅；只切换主额度不会庆祝。
- 动画订阅重建时清空池和徽章；隐藏时仍注册订阅，仅暂停全局时钟，恢复可见后能启动。
- 系统减少动态偏好响应式监听；用户或系统开启减少动态时，巡游灯、刷新弧旋转和环的过渡停止，静态状态标记保留。
- 收纳条使用归一化后的自动阈值，不再覆盖成固定 75/90。
- package.json、npm lock、Cargo.toml、Cargo.lock、Tauri 配置统一 0.6.0。

## 运行与剩余验收

当前已启动的旧 debug 进程不会因源码变更自动更新 Rust 后端。切换修复构建后才能使用新的凭据合并和请求逻辑。

如果旧版已覆盖 API Key 或网页 Token，须补填丢失的一项；新逻辑会保留另一项，但无法找回被旧版删除的 Secret。

尚未完成：真实账号双源联调、原生 WebView2 长期驻留/混合 DPI/多机器人性能验收。未发布 GitHub，也未将测试通过等同正式安装包验收。

本次未扩展到独立删除单个 Secret、逐来源持久缓存与独立限流调度、自动网页登录/续期或查询正式订阅名称。这些保留为后续增强；当前部分失败会明确提示，不伪造缺失来源数据。
