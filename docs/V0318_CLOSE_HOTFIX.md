# v0.3.18 设置窗口关闭热修复（本地候选）

基线：cc9c0be。用户运行 G 盘便携版，标题栏 X 与页面关闭按钮均触发
“设置窗口响应关闭请求超时”。本轮未读取凭据、未替换运行中的 EXE。

## 证据与边界

弹窗证明后端 request_close 已执行，但未在两秒内收到 acknowledge_close。
两种入口在 0.3.18 共用该握手。静态检查发现 ready 早于异步监听注册完成、
AwaitingFrontend 阶段重复点击会更换请求 ID、原生超时对话框持有状态锁。
这些都是关闭链路的缺陷；没有采集故障实例的前端控制台，不能断言其中某一项
是本次丢回执的唯一根因。Tauri emit 本身可以广播，不能把缺少 emit_to 单独认定为根因。

## 修改

- 等待监听注册后报告 ready；显式定向到 settings WebviewWindow。
- 增加 pending_settings_close IPC 补偿，每 500ms 检查待处理请求；事件和 IPC 按 ID 去重。
- 监听失败时 IPC 仍可处理；组件卸载时清理晚到的监听，不再报告 ready。
- 等待前端时合并重复关闭；排队请求进入可恢复的等待状态。
- 超时对话框移到阻塞任务，不持状态锁；对话框返回后复核请求，避免关闭新一轮窗口。
- 隐藏失败恢复可重试状态；关闭请求失败保留草稿，不绕过确认直接放弃。

## 验证

- Vitest：12 项通过（含 3 项关闭桥接回归）。
- Rust settings_close：3 项通过（含待处理请求及过期回执回归）。
- TypeScript / Vite 构建通过；lint 无错误，现有警告仍保留。
- 原生 X、Alt+F4、按钮、Esc 的最终 Windows 实机交互验收待完成。

## 使用与验收

产物为单独的 v0.3.18 close-fix 便携候选，不是 GitHub 正式发行，版本仍为 0.3.18。
退出旧 Pulse 后，将候选 Pulse.exe 替换原目录 EXE，保留 data 和 portable.flag；
原 EXE 建议先改名保留便于回滚。新目录启动会使用独立 data，不能据此判断账号丢失。

验收：无草稿时 X/按钮/Esc 正常隐藏；草稿时只显示一次确认；取消保留草稿；
放弃或保存后隐藏；重复打开关闭至少十次；后台悬浮栏保持运行。
仍有问题时复制关于页诊断中的 close_diagnostics，勿提供凭据或完整个人配置。
