# Round 6 开发清单：多设备同步（MVP）

日期：2026-09-23。前置：Round 2~5d 已落地（最新 1f674a9）。对应对齐审计 #18（最后一项功能缺口）。
参照 token-monitor 的多设备架构（hub 三后端 + SSE + iOS），按 Windows 单机生态裁剪为 MVP。

## 架构（MVP 裁剪决策）

- **三种模式**：关闭（默认）/ 托管（本实例开 hub）/ 连接（连到别的实例的 hub）。
  不做 Node CLI hub 与 Cloudflare Worker（无浏览器/手机端需求；后续可加）。
- **传输**：MVP 用 60 秒轮询 + 版本号比对（SSE 推送为后续增强）；hub 为实例内嵌
  线程（tiny_http crate，新依赖，锁定版本），默认端口 45539，绑定 0.0.0.0。
- **同步内容（隐私边界）**：仅日聚合（day/source/model/tokens，取自 daily_archive）
  + 设备元信息（设备名、app 版本、最后活跃时间）。**绝不传输**：转录内容、路径、
  凭据、账号身份。与 Token Monitor 的 syncPayload 同口径。
- **鉴权**：托管方生成 128 位随机 secret（一次性显示，允许重置）；所有端点要求
  `X-Pulse-Secret` 头；失败一律 401（不区分错误类型，防枚举）。

## 端点（hub 侧）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/v1/sync` | POST | 推送本设备日聚合 + 元信息；body 上限 256KB；整批校验后落 devices.json |
| `/v1/devices` | GET | 返回全部设备聚合（按设备分组，含本机），版本号变更时数据才重算 |

## 客户端行为

- 每 60s 拉取 `/v1/devices`，落盘 `sync-devices.json`（与账本库同目录）；
- 拉取失败静默保留上次数据，UI 显示"上次同步时间 + 失败状态"（诚实降级）；
- 上推自己的聚合走同一 POST（host 实例也向自己注册，统一数据面）。

## UI

1. 通用设置页新增「多设备同步」区块：模式三选（关/托管/连接）；托管态显示
   本机 LAN URL 列表 + secret（显示/复制/重置）；连接态输入 URL + secret；
   状态行显示最近同步时间/错误（诚实降级文案）。
2. 趋势仪表盘上方新增「设备」筛选/汇总行：每设备今日 tokens + 在线状态；
   数据源为合并视图（本机 daily_archive + 远端设备日聚合）。

## 安全要求（复核重点）

- secret 常量时间比较（防时序枚举）；请求体大小上限；JSON 解析失败整批拒绝；
- hub 不写任何用户可执行路径；devices.json 走 plain() 同款路径与符号链接校验；
- 绑定失败（端口占用）→ 设置态回退 off + 界面报错，不静默半开。

## 验收

- 两实例本机互通（host 45539 + client 指向 127.0.0.1:45539）端到端：
  client 的日聚合出现在 host 的设备列表（起应用人工验收）；
- 单测：secret 鉴权矩阵、payload 校验（超大/畸形/缺字段拒绝）、轮询降级、合并视图；
- 门禁全过；README 多设备章节 + 隐私边界披露。
