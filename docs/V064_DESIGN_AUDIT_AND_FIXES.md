## 为什么“30 分钟自动续期”仍出现 401

旧代码没有独立的 30 分钟续期定时器，而是依赖查询失败后命中特定错误文字。原条件要求整体 error_code=auth，且 error_message 包含“Token 已过期”或 expired。

截图场景中，套餐 HTTP 401，API 余额成功返回 ¥15.00：
1. HTTP 401 的文案不含上述关键字。
2. merge/parse 因现金读数成功，把整体 state 设为 live、error_code 清空，套餐错误只保留在文字警告中。
3. 即使进入续期，隐藏窗口第一次读到旧 Cookie 就可能返回成功；没有确认 Token 更新、所属会话和接口可用性。
4. 自动保存会 bump 账号代次，而重试仍使用旧代次，结果可能被丢弃。

修复后使用 web_auth_required 结构化标志：整体仍可显示现金余额，网页来源认证失败独立触发续期。已知 JWT access exp 距离到期 90 秒以内，也在正常刷新后尝试续期；不凭空假定每个 Token 固定 30 分钟。每次最多一次重试，账号/Profile 维度冷却 5 分钟，浏览器操作全局串行，失败保留现金读数及明确提示。

## 当前续期设计的边界

- 保存一段 Token 不等于持有能续期的浏览器登录会话。手动从其他浏览器复制的 Token、被撤销会话、短信/扫码授权失效，可能必须重新网页登录。
- 隐藏窗口复用 Pulse 自身的 WebView2 登录环境；本轮没有导入用户其他浏览器的 Cookie，也没有提取真实凭据用于终端诊断。
- 多个账号仍共用浏览器会话环境。现已阻止自动串写，但不承诺多个独立网页登录会话同时无感续期。每账号独立 WebView2 Profile 是后续设计项；不能只设置 data_directory 就宣称隔离，因为全局 WEBVIEW2_USER_DATA_FOLDER 可覆盖它。
- 会话身份读取只用于避免账号混淆，不构成 JWT 签名验证；真正可用性仍须由 StepFun 服务返回验证。
- 暂未获得官方网站“必须每 30 分钟刷新”的契约证明；不使用伪造 refresh API，不无限重放 401。
- 加油包当前仍合计展示：最早到期时间不表示所有加油包同日到期；逐包展示、真实分页协议与去重规则仍需脱敏服务样本验证。

WebView2 环境变量覆盖规则参考 Microsoft 官方资料：https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/webview2-idl （UserDataFolder override）。
