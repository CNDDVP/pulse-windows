# v0.4.1 详情窗口首次布局候选修复

基线：9a5c230（包含前一轮关闭协调器热修复）。

用户现象：冷启动第一次打开详情，卡片狭窄、裁切、距离悬浮栏过远；第二次正常。
静态证据：初始窗口 380×340，与运行时 340×360 不一致；代码先设置物理尺寸再跨屏
移动，立即 show，最后才发送账号和布局。尚未现场复现具体显示器组合，不声称唯一根因已证实。

修改：统一初始尺寸；主线程先移动处理目标屏幕 DPI，再设置物理尺寸；账号、位置及
尺寸合并为带请求 ID 的快照。前端加载内容后连续两次确认 CSS 视口×DPR 与目标物理
尺寸匹配，才允许显示。隐藏的 WebView 可能暂停 rAF，确认采用有界定时检查。
初次错过事件时可读取快照，迟到回复不能显示已取消或已被替换的详情；每个请求只显示一次。

验证：Vitest 13 项通过；TypeScript/Vite 与 cargo check 通过。
待实机：全退出冷启动首次悬停；100/125/150/175/200% DPI、混合 DPI；快速移开、
切换账号、跨屏、四窗口 Antigravity 内容滚动；检查无空白窗口或再次出现错位。

候选不覆盖正在运行的程序，不含用户 data；使用前从托盘退出 Pulse，备份旧 EXE，
仅替换原目录 Pulse.exe，保留 data 和 portable.flag。版本仍为 0.4.1，包名以 detail-fix 区分。
